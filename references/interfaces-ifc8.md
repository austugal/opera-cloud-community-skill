# Interfaces, IFC8, and OXI

Product names, supported versions, network topology, protocols, and setup steps depend on the
specific OPERA generation and licensed interface. IFC8 and OXI are not synonyms for OHIP or for each
other. Verify the applicable product and release before following a procedure.

## Interface types in OPERA

OPERA environments can be integrated with on-property and external systems through supported
interfaces. Common use cases include:

- Payment interfaces (card authorisation and settlement through a payment platform).
- Point of sale (POS) for posting food, beverage, and retail charges to guest folios.
- Door lock / key systems.
- Telephone / call accounting.
- Voice mail, minibar, pay TV / in-room entertainment, and similar in-room services.
- Back-office finance exports (handled as exports rather than live interfaces; see
  `backoffice-export.md`).
- Channel and distribution connectivity (handled through Distribution APIs and OXI; see
  `distribution-channels.md`).

## IFC8

IFC8 is a named Oracle Hospitality interface component associated with particular supported
integration deployments. Do not assume all OPERA Cloud interfaces use IFC8 or that its topology,
transport, and protocol are identical across releases and products. Check Oracle documentation for
the specific interface and version.

Oracle's Hotels documentation index (checked 2026-10-15) lists Hotel Property Interface releases up
to 8.17 and, separately, an IFC8 Interface (FIAS, XML POS) entry under OPERA 5 Integrations with no
release number. Confirm which of these applies to the interface in question before quoting a
version.

Where the documented architecture uses IFC8, concepts to verify include:

- IFC8 mediates between OPERA and a device or system, translating messages both ways.
- An interface instance is configured with the connection parameters and the message behaviour for
  the specific external system.
- Authentication parameters configured on the OPERA side must match those configured on the
  interface side; a mismatch is a common cause of an interface failing to start or link.
- Interfaces are licensed and enabled per property; an interface must be both configured and active
  to pass traffic.

For a connection problem, verify the configured endpoint, credentials, entitlement, certificates,
network path, component health, and logs on both sides. Do not restart a production component
without evidence, authorization, and an impact/rollback plan.

## OXI / OPERA Exchange Interface

OXI (OPERA Exchange Interface) is a separate OPERA integration product used in supported
deployments. Its functions and compatibility differ from OHIP and Oracle Hospitality Distribution;
verify the exact OXI version and integration design.

Concepts:
- Translation tables map external values (rate codes, room types, market segments, source codes) to
  OPERA values and back.
- During a channel manager migration, the OXI translation layer is what gets reconfigured while the
  external codes typically stay the same (see `distribution-channels.md`).
- OXI message flow covers both inbound (reservations from the external system) and outbound
  (availability, rates, restrictions to the external system).

## Interface configuration in OPERA Cloud

The available interface configuration surfaces and API modules depend on product, release, and
entitlements. Confirm exact menu paths, API module names, and fields in the release-specific
documentation; do not treat a module label as proof that an operation is enabled.

## Practical interface troubleshooting checklist

1. Is the product/interface supported, licensed, entitled, and enabled for this property?
2. Do the authentication / connection parameters match on both the OPERA side and the external side?
3. Is the interface controller running and the link reported up?
4. Are messages being generated by the triggering action (for example a POS charge) at all?
5. If messages generate but do not arrive, is it a translation/mapping gap or a transport problem?
6. Check the interface logs on both sides for the specific rejected message before changing
   configuration.
